## Global conventions (apply to every task)

- **NO hardcoded prices / packs / limits anywhere in code.** Everything (quota caps,
  per-plan model map, addon packs) is DB-backed and admin-managed from the admin
  dashboard — the `plan_pricing` / `/admin/plan-limits` pattern (`admin-plans.ts`).
  Migration seeds are only starter DEFAULTS the admin owns and edits live; code reads

  `089` (already drafted, apply with admin approval) = `resource_packs` admin table.

  effective once the migration is applied — keep `schema.prisma` in sync by hand.

```ts
// GET /products/video-styles → PUBLISHED rows, kind VIDEO, plans has retailer.plan
//   select: slug, label, description, thumbnail_url (NO prompt — server-side only)
// POST /products/:id/videos/ai-generate
//   body: { style_slug: string, aspect: z.enum(['9:16','16:9','1:1','4:5']) }

//     5. model = (await prisma.planVideoModel.findUnique({ plan }))?.model ?? fallback map
//        (validate against VIDEO_MODELS keys → 422 if bad)
//     6. addAiVideoJob({ job_id: createId(), retailer_id, product_id, photo_id,
//                       style_slug, prompt: style.prompt, model, aspect,
//                       seconds: 5 (fixed in Phase 1 — curated styles are 5s),
//                       style_id: style.id })
// GET /products/:id/videos/ai-generate/status?job_id= → processing | ready {video} | failed
//   (Redis via video job status helper; fallback: ProductVideo row with
//    metadata.video_job_id === job_id → ready {video_id, url} — mirror the studio
//    completed-row fallback in products-studio.ts)
// GET /products/:id/videos/ai-generate/quota → { plan, used, limit, remaining, period }
```

### 7.3 Job — `apps/api/src/jobs/generate-promo-video.ts` (new)

Copy `jobs/studio-shoot.ts` structure. Steps, in order:

1. **Re-verify ownership** at execution (queue is a trust boundary): product + main
   photo (or `photo_id`) belong to `retailer_id`.
2. Resolve a fetchable source URL (`studioSourceUrl` pattern — public URL as-is,
   relative → `getDownloadPresignedUrl(r2_key, 3600)`).
3. `setVideoJobStatus(job_id, { status: 'processing', progress: 0, etaMs: 90_000 })`
   (new helper in `lib/fal-video.ts` or a `lib/promo-video-status.ts` mirroring
   `setStudioJobStatus` — Redis key per job, TTL ~1h).
4. `generateImageToVideo(sourceUrl, { model, motionPrompt: style.prompt, aspect,
   seconds, onProgress })` → `onProgress` writes `{ progress, etaMs }` to the same key.
5. `uploadBuffer(R2_PATHS.productVideo(retailer_id, product_id, '<createId()>.mp4'),
   mp4, 'video/mp4')` — the lib already returned a web-playable MP4.
6. `prisma.productVideo.create({ product_id, retailer_id, r2_key, public_url,
   duration_sec: seconds, source: 'AI_GEN', is_main: !hasVideo })` — `hasVideo` =
   any existing ProductVideo for the product (same as ken-burns).
7. `setVideoJobStatus(job_id, { status: 'ready', video_id, url })` **after** the row
   exists (never before — the status endpoint's row fallback depends on it).
8. `incrementUsage(retailer_id, 'AI_VIDEO')` + `recordAiVideoUsage(retailer_id,
   style_slug)` (new fn in `lib/ai-usage.ts`, mirroring `recordBflStudioUsage`) +
   `studioStyle.update({ id: style_id, usage_count: { increment: 1 } })` — all
   `.catch(log)` non-fatal, matching the studio job.
9. Failure path: `setVideoJobStatus(job_id, { status: 'failed', error: safeMsg })`
   then rethrow (BullMQ marks failed; **no auto-retry — every run costs credits**).
