## Findings
| id | sev | file:line | issue | fix |
| --- | --- | --- | --- | --- |
| F1 | P1 | `passport/[...path]/route.ts:44-52`, `my-style/[...path]/route.ts:27-37`, all other proxies | No proxy forwards the client IP. `grep -rn "x-forwarded-for\|x-real-ip" apps/web/src` → no match. API keys its global limiter on `request.ip` (`apps/api/src/index.ts:143`, 200/min) and hashes `request.ip` into `ConsentEvent`/`PassportSession` (`passport-otp.ts:140,158`). Behind the proxy `request.ip` is the web container, so every shopper shares one 200/min bucket and every `ip_hash` is identical. Code-confirmed; **runtime not verified** (no staging access). | Forward the edge-supplied client IP in a shared helper. **Depends on owner decision `trustProxy` (T1.8)**: with `trustProxy: true`, Fastify takes the leftmost XFF, spoofable unless the edge overwrites it. |
| F2 | P2 | `reviews/product/[productId]/route.ts:11` | `productId` interpolated into the upstream URL without `encodeURIComponent`. `new URL('https://api.x/v1/public/reviews/product/../../../admin/retailers').href` → `https://api.x/v1/admin/retailers`. Next decodes `%2F` in dynamic params (not verified at runtime), so an anonymous caller can steer this GET to any API path. No cookie is forwarded, so impact is limited to unauthenticated API routes (bypasses web-side allowlists; response cached 60 s). Also no try/catch. | `encodeURIComponent(productId)`. |
| F3 | P2 | `passport/[...path]/route.ts:62-65` | `res.headers.get('set-cookie')` joins multiple Set-Cookie values with `, `, producing an invalid header. Latent: every passport route sets exactly one cookie today (`setPassportCookie`, logout `passport-session.ts:59`, delete `passport-data.ts:180`). | `getSetCookie()` loop with `append`. |
| F4 | P2 | `passport/[...path]/route.ts:59` | Account-specific responses (`/me`, `/export`, `/wishlist`, `/preferences`) carry no `cache-control` and lose the upstream `content-type` (becomes `text/plain`). `my-style` sets `private, no-store` (`:48`) and content-type (`:45-46`); passport does not. | Copy the two `my-style` header lines. |
| F5 | P2 | `passport/[...path]/route.ts:13` vs API | API routes with no proxy path and no web caller: `DELETE /wishlist/:productId` (`passport-wishlist.ts:89`), `POST /stores/:retailerId/mute\|remove` (`passport-stores.ts:42,85`). Allowlist entry `profile` has no API route (grep of `routes/public/passport/*.ts` finds none); `try-on/consent` is allowed for POST but the API only has GET (`passport-tryon.ts:34`). Web grep for `/mute`, `/remove`, `wishlist/`, non-admin `method: 'DELETE'` → no match. Either dead API or missing UI. Not a bug today; product decision. | Delete the API routes, or add proxy paths + UI. Drop `profile` from the list. |

Not a finding (P3): `revalidate/route.ts:31` compares the secret with `!==` (not constant-time). Caller needs the secret and it only triggers `revalidatePath`.
