| F1 | P1 | `apps/web/src/app/sw.ts:118` (`...defaultCache`) | Authenticated responses are written to Cache Storage and nothing clears them. Serwist `defaultCache` (`@serwist/next/dist/index.worker.mjs:155-165`): every same-origin `GET /api/*` → `NetworkFirst`, cache `apis`, 24 h, 10 s network timeout; `:207-216`: every cross-origin GET → `NetworkFirst`, cache `cross-origin`, 1 h. No earlier rule in `sw.ts` matches `/api/passport/*` or `/api/my-style/*` (only `/api/c/` and store proxies, `:50-55`) or the retailer `/v1/retailers/*` calls (only `/v1/admin`). So `/api/passport/me`, `/export` (full data export), `/wishlist`, `/preferences`, `/stores`, and the retailer's Bearer-token `GET /v1/retailers/me/invoices` (`billing/page.tsx`) are stored. No code calls `caches.delete` (`grep -rn "caches\.delete\|caches.keys" apps/web/src` → none). On a shared phone, after shopper A logs out, shopper B going offline (or >10 s network) gets A's cached `/me`/export. `no-store` on the response (RC-084) does not stop these strategies, which cache any 200. Built `public/sw.js` contains `cacheName:"apis"` and no passport exclusion. **Runtime not exercised** (needs a prod build in a browser with a session). | Add two `NetworkOnly` rules before `...defaultCache`: all same-origin `/api/` (the cached public proxies keep their earlier explicit rule) and all `/v1/` paths (widen the `/v1/admin` rule). Drop the stale caches on SW activate. Diff below. |
| F2 | P1 | API `routes/public/public-retailers/public-retailers-sitemap.ts:83-84` | Sitemap lists every `status: 'ACTIVE'` collection, including ones made for one customer (`Collection.customer_id`, set by `collections.ts:130` and the AI-picks route).
