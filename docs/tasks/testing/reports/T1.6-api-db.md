## Findings

| ID | Sev | file:line | Issue | Proof | Fix |
| --- | --- | --- | --- | --- | --- |
| F1 | P2 | Supabase Auth settings | Leaked-password protection is off. Retailers log in with phone OTP and the admin/team password login uses its own hashing (`team-auth.ts`), not Supabase Auth, so practical impact is small. | Advisor `auth_leaked_password_protection`, level WARN, <https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection>. | Owner dashboard toggle (no code). Ignore if no password sign-in is enabled in Supabase Auth. |
| F2 | P2 | `routes/admin/admin-data.ts:57-79` | The 30 s console timeout is a `Promise.race`; it rejects the HTTP call but does not cancel the query in the database. A super-admin `SELECT pg_sleep(...)` or heavy join keeps running on the replica after the "timeout". Admin-only, replica-only, so low risk. | Code quote: `Promise.race([replica.$transaction(...), timerPromise])`. No `statement_timeout` set. | Add `SET LOCAL statement_timeout = '30s'` beside `SET TRANSACTION READ ONLY`. |
| F3 | P2 | `routes/admin/admin-data.ts:33-45` | The read-only gate is a keyword/semicolon heuristic (`SELECT/EXPLAIN/WITH`, `semicolonCount > 1`). The real protection is `SET TRANSACTION READ ONLY`, so this is not a vulnerability. The heuristic ignores `$$` quoting and permits one `;`. By design a super-admin can read any table, including `team_members.password_hash` and encrypted integration rows. | Code quote. Not exploited; reasoning only. | Keep. Optionally block `team_members` and `integration_settings` in the console. Owner decision. |
