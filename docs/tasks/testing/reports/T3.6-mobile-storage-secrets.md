| T3.6-a | **P1** | `apps/mobile/src/lib/api/client.ts:129-137` | **Forced logout leaves the previous account's data on the device.** When token refresh fails, the client clears only `auth_token` + `refresh_token` + the request cache and redirects. It does not call `queryClient.clear()` or `clearPersistedCache()`, and it leaves `retailer_id`/`staff_*` keys (only `signOut` clears `AUTH_KEYS`). The persisted cache is not scoped by account (`queryKey: ['customers', search]`, `app/(tabs)/customers.tsx:117`), and `_layout.tsx:348-351` restores it at app start, before auth. On a shared shop phone, the next person to sign in (another staff member or another retailer) sees the previous account's customer names/phones and enquiries until each query refetches (`staleTime: 60_000`, `_layout.tsx:86`). The JSON file also stays on disk. | `client.ts`: `await clearToken(); await deleteItem('refresh_token'); clearRequestCache(); redirectToAuth()`. Manual logout `settings/index.tsx:1231-1232`: `queryClient.clear(); await clearPersistedCache();` | Route every sign-out through one place: on `emitAuthChange({ authed: false })` the AuthProvider runs the full `signOut` cleanup (all `AUTH_KEYS`, `queryClient.clear()`, `clearPersistedCache()`).
