## Findings

| ID | Sev | file:line | Issue | Proof | Fix |
| --- | --- | --- | --- | --- | --- |
| F1 | P1 | `routes/customers.ts:96-98` (list), `:130` (detail) | Phone masking for manager / salesperson / support delegate is bypassable. Both handlers spread the whole customer row (`...c`, `...customer`) and only overwrite `phone`. The row also carries `phone_hash`, an unsalted SHA-256 of the bare 10-digit number (`customers.ts:43`; `normalizeIndianPhone` returns bare digits, `utils/index.ts:162-168`). Managers may `GET /v1/customers` and `/v1/customers/:id` (`auth.ts:221`, non-exact prefix); support sessions too (`auth.ts:282`). The mask `98•••••210` leaves 5 unknown digits, so the hash reverses in about 100k tries. RC-066 shape (masking per field, not at the source). | Synthetic number `9876543210`: `mask 98•••••210 -> recovered 9876543210 after 76544 hashes` (node, sub-second). Code: `...c, phone: maskPhoneForRequest(request, c.phone)`. | Strip `phone_hash` for non-owners in both handlers. Diff below. |
| F2 | P2 | `routes/team/team-helpers.ts:71` | Public-path bypass uses `request.url.startsWith(p)`. A future team route whose path merely starts with `/v1/team/login`, `/otp/send` etc. (e.g. `/login-history`) is silently unauthenticated, and `request.url` includes the query string. None exists today, so latent. | Code quote: `if (publicTeamPaths.some((p) => request.url.startsWith(p))) return;`. | Match `request.routeOptions.url` exactly, as `auth.ts` does. |
| F3 | P2 | `routes/team/*` | Admin has a derived "every route refuses no credentials" test; team has none, so a new team plugin that forgets the hook fails open (the `adminSettingsRoutes` history in the admin test header). All 8 plugins have the hook today. | Hook count = 1 per file, route counts 1-6. | Copy the admin test pattern for `/v1/team`, excluding the 5 public paths. |
